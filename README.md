# Ваучеры: тестовое задание

Приложение, в котором администратор задаёт пользователям запас ваучеров
на продукты, а пользователи активируют их. Каждая активация уменьшает
запас на один и записывается в историю. Когда ваучеров не осталось,
активация невозможна.

**Стек:** Rust, Axum, sqlx, PostgreSQL / React, TypeScript, shadcn/ui

## Запуск одной командой

Нужен только [Docker](https://www.docker.com/products/docker-desktop/).

```bash
docker compose up --build
```

Первая сборка занимает несколько минут. После запуска:

| Сервис   | Адрес                  |
|----------|------------------------|
| Frontend | http://localhost:5173  |
| Backend  | http://localhost:3000  |
| Postgres | localhost:5433 (postgres / root, БД `project`) |

База данных создаётся автоматически. Бэкенд при старте применяет
миграции, в том числе создаёт тестовых пользователей и продукты.

Сбросить данные и начать с чистой базы:

```bash
docker compose down -v
docker compose up --build
```

## Как пользоваться

1. Выберите пользователя в верхнем списке.
2. В форме администратора выберите продукт, укажите количество и сохраните.
   Новое значение заменяет текущий запас.
3. В таблице запаса нажмите «Активировать». Запас уменьшится на один,
   запись появится в истории.
4. Когда запас равен нулю, кнопка отключена. Если запас закончился в
   другой вкладке, сервер вернёт ошибку и интерфейс покажет сообщение
   «Ваучеров на этот продукт не осталось».

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/users` | список пользователей |
| GET | `/products` | список продуктов |
| GET | `/users/{user_id}/vouchers` | запас по всем продуктам (если не задан, 0) |
| POST | `/users/{user_id}/products/{product_id}/activate` | активировать ваучер |
| GET | `/users/{user_id}/activations` | история активаций |
| PUT | `/admin/users/{user_id}/products/{product_id}/vouchers` | задать запас, тело `{"quantity": 5}` |

Ошибки возвращаются как `{"error": "текст"}` с кодами:
400 (некорректные данные), 404 (нет пользователя или продукта),
409 (ваучеров не осталось), 500 (внутренняя ошибка).

## Структура данных

- `users`, `products`: справочники, создаются миграцией.
- `user_vouchers (user_id, product_id, quantity)`: запас ваучеров на
  пару «пользователь + продукт». Составной первичный ключ, `CHECK (quantity >= 0)`.
- `activations (id, user_id, product_id, activated_at)`: история.

## Ключевое решение: активация

Активация выполняется в одной транзакции:

```sql
UPDATE user_vouchers
SET quantity = quantity - 1
WHERE user_id = $1 AND product_id = $2 AND quantity > 0
RETURNING quantity
```

Проверка остатка и списание делаются одним запросом, поэтому два
одновременных запроса не могут списать последний ваучер дважды: второй
увидит `quantity = 0` и не обновит строку (ответ 409). Затем в той же
транзакции добавляется запись в `activations`. Если что-то упало, не
сохраняется ни списание, ни запись. Дополнительно ограничение
`CHECK (quantity >= 0)` в базе не даёт запасу уйти в минус.

## Разработка без Docker

Нужны Rust, Node.js 22+ и PostgreSQL.

```bash
# backend
cd backend
echo "DATABASE_URL=postgres://postgres:root@localhost:5432/project" > .env
cargo run            # миграции применятся при старте

# frontend (в другом терминале)
cd frontend
npm install
npm run dev          # http://localhost:5173
```

Адрес API для фронтенда задаётся переменной `VITE_API_URL`
(по умолчанию `http://localhost:3000`).
